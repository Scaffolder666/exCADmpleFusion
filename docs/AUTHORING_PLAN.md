# 案例制作流程：思路记录

> 状态：**已实现**（在 `fusion` 与 `fusion-him` 分支）。实际做法与下面最初的思路不同的地方见文末"实现"。格式规范见 `fusion` 分支的 [`docs/EXAMPLE_FORMAT.md`](https://github.com/Scaffolder666/exCADmpleFusion/blob/fusion/docs/EXAMPLE_FORMAT.md)。

## 问题

制作一个 Design Example 需要三份材料：提取草稿、文字稿、标注。前两份已有现成办法，**只有标注靠手写 `annotation.json`**，比较费手。

## 现状

| 步骤 | 做法 | 是否需要新工具 |
|---|---|---|
| 录制 | Fusion 照常建模，设计师边做边说；任意录屏软件同时录屏和录音（OBS、系统自带录屏） | 否 |
| 提取 | 插件按钮 **Extract example draft…** → `*.extract.json` | 否（待用真实 `.f3d` 验证：装配体坐标、耗时） |
| 转写 | 任意转写工具导出 `.srt`（Whisper、Otter、剪映、飞书妙记等） | 否 |
| **标注** | 手写 `annotation.json`：每步的起止时间、特征名、推理摘要，以及可选的决策、适用范围、依赖 | **视工作量而定** |
| 合成 | `tools/build_package.py` | 否 |

估计：一个约 10 步的案例，标注约 1–2 小时，主要花在对照录像找时间点和阅读文字稿上。

## 计划：先轻后重

### 第一步：模板 + 检查脚本（先做）

- `templates/annotation.template.json`：填空式模板，每个字段旁注明含义、是否必填、内容从哪里来。
- `tools/check_annotation.py draft.extract.json annotation.json transcript.srt`：
  - 时间段是否重叠、是否超出录音长度；
  - 特征名是否存在于草稿中、是否按时间轴顺序、是否被重复使用；
  - 必填项是否缺失（`brief.goal`、每步的 `summary`）；
  - 列出**没有被任何步骤包含的特征**，以及**没有落在任何步骤里的文字稿片段**，提醒标注者检查遗漏；
  - 对每一步打印其时间段内的文字稿，方便写摘要。
- 用第一个真实案例手工走一遍，记录哪些环节最费时。

### 第二步：标注页面（只有在第一步明显繁琐时才做）

做一个本地 HTML 页面，无需安装：

- 左侧：录像播放器 + 随播放滚动的文字稿；
- 下方：从草稿读出的特征列表（按时间轴顺序）；
- 操作：在录像上标记起止时间 → 勾选特征 → 写摘要（可选：决策、适用范围、依赖）→ 生成一个步骤；
- 导出 `annotation.json`，并在页面内运行与检查脚本相同的检查。

预估工作量：约半天。适用于案例超过十个左右，或需要由他人标注的情况。

## 原则

- 推理只来自设计师说过的话；工具只帮助定位和整理，**不自动生成摘要或决策**。
- 标注与提取分开存放：重新提取 `.f3d` 不会覆盖标注。

## 实现（2026-11）

最终做成了 AI 辅助的流程，代码在 `fusion` 分支：

1. **录制时就记下时间**（`exCADmple: Record tutorial`，`core/session_recorder.py`）：设计师边建模边说时，插件记录用到的工具、每个特征出现的时间、选中的位置（作为鼠标轨迹）。这样就不用再对着录像手工找每一步的时间点。
2. **AI 切分步骤**（`tools/author.py`，`core/ai_segment.py`）：Claude 根据特征出现时间、工具和文字稿，提议怎么把录制切成步骤、每步的标题（尽量用设计师自己的话）。它不写任何推理。提议会被检查（特征按顺序、每个只用一次、时间不重叠），不合格或没有 API 凭据时改用按特征的规则切分。
3. **人工检查**（`ui/author.html`）：在浏览器里对着录像调整标题、起止时间、包含的特征，可拆分、合并，然后导出 `annotation.json`。
4. **转写**仍用任意工具，或本地的 `tools/transcribe.py`（faster-whisper）。

原计划中的"检查脚本"由 `tools/author.py` 的检查和 `ui/author.html` 的实时检查代替；"填空模板"不再需要，因为 `annotation.json` 由工具生成。
